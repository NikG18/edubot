# Юридические документы и фиксация подтверждений

Редакция комплекта публичных документов: `2026-10-06-r1`.

## Отмена перенос и возврат

Оферта, регламент возвратов и раздел 6.4 агентского договора согласованы на 06.10.2026.
Правила возврата доступны ученику, репетитору и администратору в разделе «Документы»
Telegram/VK, а также перед оплатой. Отказ менее чем за 24 часа не создаёт автоматический
штраф или оплату занятия. Дополнительные допустимые расходы Zoom подтверждаются по
конкретному заказу; предел на пользователя за оплаченный месячный период — меньшая
из доказанных расходов и 20% фактической цены подписки, максимум 500 рублей.

- [Публичная оферта](02_student_offer.md) · [Word](02_student_offer.docx)
- [Регламент возвратов](09_refund_rules.md) · [Word](09_refund_rules.docx)
- [Агентский договор](01_agent_agreement.md)

`legal_common.py` содержит версию и SHA-256 всех документов. Кнопки новой версии
ведут на `legal/versions/2026-10-06-r1/`; прежние тексты сохранены отдельно в
`legal/versions/2026-09-09-r1/`. Старые события акцепта не переписываются.
Новые условия применяются после публикации к новым заказам согласно разделу 9 оферты.
Политика ПД и отдельные согласия включены в комплект с прежним содержанием.

Кнопка автоматического зачёта поздней отмены/неявки как проведённого занятия удалена.
Старый callback не создаёт списание или закрывающий чек. Неявка и допустимые расходы
требуют отдельной проверки; автоматического начисления расходов Zoom нет.

## Обновление работающих ботов

Документы по старым публичным ссылкам `main/legal` обновляются при публикации в `main`.
Для обновления кнопок, журналирования версии и обработчиков на VPS после публикации:

```bash
cd /home/nikg18/edubots/bot-legal-test
git fetch origin main
git merge --ff-only origin/main
sudo systemctl restart telegram-bot.service vk-bot.service
sudo systemctl --no-pager --full status telegram-bot.service vk-bot.service
```

Перед обновлением рабочее дерево должно быть чистым; при локальных изменениях или
ошибке fast-forward обновление останавливается. Каталог `/home/nikg18/edubots/bot`
не используется для этого обновления. Если задан `LEGAL_DOCS_BASE_URL`, он должен
указывать на актуальный `main/legal` или на опубликованную копию каталога с `versions/`.

## Публичные документы

В `legal/` хранятся редакции документов, которые можно показывать пользователям и репетиторам через Telegram/VK. После merge production-ссылки по умолчанию ведут на `main/legal`. Для smoke-теста feature-ветки задайте:

`LEGAL_DOCS_BASE_URL=https://github.com/NikG18/edubot/blob/feature/legal-documents/legal`

В production рекомендуется заменить GitHub на стабильные публичные URL собственного домена/статического хостинга и сохранять старые редакции по неизменяемым адресам.

Не размещать в публичном репозитории заполненные анкеты репетиторов, ответы Яндекс Формы, персональные экземпляры согласий или иные закрытые персональные данные.

## Яндекс Форма репетитора

Первичный сбор данных и юридических подтверждений репетитора предполагается через Яндекс Форму. В форме должны быть отдельные действия:

1. Акцепт агентского договора.
2. Согласие на обработку персональных данных.
3. Отдельное согласие на распространение персональных данных.

Для согласия на распространение необходимо сохранять конкретный состав разрешённых категорий/площадок, а не только общий флаг. Предустановленные отметки не использовать.

После импорта ответа формы вызывается `record_tutor_yandex_acceptance(...)` из `legal_common.py`; в `external_ref` передаётся идентификатор ответа формы.

## Журнал legal_acceptances

Таблица создаётся лениво при первом юридическом событии и хранит:

- субъект и роль;
- платформу/источник;
- тип, версию и SHA-256 документа;
- действие и результат;
- booking ID при наличии;
- внешний идентификатор (например, response ID Яндекс Формы);
- metadata;
- timestamp.

Для одного `booking_id`, одной версии документа и одного канала событие `presented_before_payment` записывается идемпотентно: повторное открытие оплаты не создаёт новые одинаковые строки. Уже существующие тестовые повторы не удаляются, поскольку являются фактической историей тестирования.

Успешная оплата занятия фиксирует отдельное событие акцепта оферты; оно создаётся только при реальном переходе брони в оплаченный статус. Абонементы фиксируются отдельно после успешной активации.

## Что ещё не входит

- автоматический импорт/API Яндекс Формы;
- фискальные `AgentData`/`SupplierInfo` T-Банка;
- договорный алгоритм комиссии 100/60 и перенос достигнутой ставки;
- отдельный процесс правовой проверки неявки, частичных возвратов и расходов;
- полный процесс удаления/анонимизации ПД и маскирование чувствительных логов.
