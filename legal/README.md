# Юридические документы и фиксация подтверждений

Редакция комплекта публичных документов: `2026-09-03-r1`.

## Публичные документы

В `legal/` хранятся редакции документов, которые можно показывать пользователям и репетиторам через Telegram/VK. После merge production-ссылки по умолчанию ведут на `main/legal`. Для smoke-теста feature-ветки задайте:

`LEGAL_DOCS_BASE_URL=https://github.com/NikG18/edubot/blob/feature/legal-documents/legal`

В production рекомендуется заменить GitHub на стабильные публичные URL собственного домена/статического хостинга и сохранять старые редакции по неизменяемым адресам.

Не размещать в публичном репозитории заполненные анкеты репетиторов, ответы Яндекс Формы, персональные экземпляры согласий или иные закрытые персональные данные.

## Яндекс Форма репетитора

Первичный сбор данных и юридических подтверждений репетитора предполагается через Яндекс Форму. В форме должны быть отдельные действия:

1. Акцепт агентского договора.
2. Согласие на обработку персональных данных.
3. Отдельное согласие на распространение персональных данных.

Для согласия на распространение необходимо сохранять конкретный состав разрешённых категорий/площадок, а не только общий флаг. Предустановленные отметки не использовать.

После импорта ответа формы вызывается `record_tutor_yandex_acceptance(...)` из `legal_common.py`; в `external_ref` передаётся идентификатор ответа формы.

## Журнал legal_acceptances

Таблица создаётся лениво при первом юридическом событии и хранит:

- субъект и роль;
- платформу/источник;
- тип, версию и SHA-256 документа;
- действие и результат;
- booking ID при наличии;
- внешний идентификатор (например, response ID Яндекс Формы);
- metadata;
- timestamp.

Для одного `booking_id`, одной версии документа и одного канала событие `presented_before_payment` записывается идемпотентно: повторное открытие оплаты не создаёт новые одинаковые строки. Уже существующие тестовые повторы не удаляются, поскольку являются фактической историей тестирования.

Успешная оплата занятия фиксирует отдельное событие акцепта оферты; оно создаётся только при реальном переходе брони в оплаченный статус. Абонементы фиксируются отдельно после успешной активации.

## Что ещё не входит

- автоматический импорт/API Яндекс Формы;
- фискальные `AgentData`/`SupplierInfo` T-Банка;
- договорный алгоритм комиссии 100/60 и перенос достигнутой ставки;
- no-show workflow;
- полный процесс удаления/анонимизации ПД и маскирование чувствительных логов.
