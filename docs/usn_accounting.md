# Бухгалтерия ИП: УСН «Доходы», 2026

В Telegram у администратора появляется кнопка **Бухгалтерия / КУДиР**.
Подтверждённые владельцем параметры: ставка 6%, начало УСН 07.08.2026,
нет работников и выплат обычным физлицам, не являющимся ИП/самозанятыми.
Профиль создаётся один раз, повторный запуск не перезаписывает настройки.
Владелец и ИНН берутся из `FISCAL_OPERATOR_NAME` / `FISCAL_OPERATOR_INN`.

## Что автоматизировано

- Сбор операций бота при открытии раздела, сверки, расчёта, импорта и выгрузки.
- Разделение собственных оплат и транзитных денег сторонних репетиторов
  по сохранённым реквизитам поставщика. Изменение карточки репетитора не меняет
  классификацию старой оплаты. Неизвестный поставщик требует сверки.
- Целая оплата абонемента учитывается один раз по ID платежа. Расходование
  занятий, повторный webhook и закрывающий чек не создают новый доход.
- Агентское вознаграждение связывается с неизменяемым отчётом репетитору.
- КУДиР: PDF с титульным листом и графами раздела I по кварталам,
  CSV раздела I, отдельный аудиторский реестр всех операций.
- Расчёт налога нарастающим итогом, авансов, уменьшения на взносы,
  уменьшения ранее начисленного аванса при возвратах, разницы с погашенным УСН.
- Снимок каждой PDF-выгрузки, SHA-256 и исходные данные сохраняются в БД.
  Последующие исправления не меняют ранее сохранённую выгрузку.

## Что требуется перед первым расчётом

1. Внести реквизиты расчётного счёта и банка для титульного листа.
2. Скачать шаблон CSV в «Правила и шаблон».
3. Разобрать операции бота по выписке и документам; добавить поступления вне бота.
4. Настроить разрешённое уменьшение на взносы либо явно выбрать расчёт без него.
5. Проверить возвраты и погашения именно УСН по данным ЕНС.
6. Отметить дату завершённой сверки. До этого расчёты помечены предварительными.

Подключения к банку нет. CSV — установленный шаблон, а не произвольная сырая
выписка любого банка. Дата webhook/создания отчёта не подставляется как дата
налогового дохода. Для эквайринга нужна дата зачисления средств по выписке;
сумма собственного дохода — полная сумма покупателя до удержания комиссии банка.
Сам отчёт репетитору ещё не является подтверждением фактического удержания
вознаграждения. Для комиссии укажите первичный документ и дату удержания/зачёта.

Старые события без достоверных реквизитов, платежи до начала УСН, отменённые
отчёты и ошибочные источники исключаются с объяснением (`exclude`), а при
необходимости подтверждённый доход вносится отдельной строкой с документом.
Не исключайте реальное поступление только ради завершения сверки.

## Формат CSV

UTF-8 (BOM разрешён), разделитель `;`, точный заголовок:

```csv
operation_id;date;document;kind;amount;source_key;original_id;description;tax_year
bank-001;10.08.2026;Выписка №15;income;2500;payment:12345;;Оплата занятия;2026
report-001;16.09.2026;Отчёт и зачёт №1;agent_fee;625;report:1;;Удержанное вознаграждение;2026
refund-001;20.09.2026;Возврат №5;refund;500;;bank-001;Частичный возврат;2026
usn-001;10.04.2027;Справка ЕНС;tax_payment;12000;;;Погашен УСН за 2026;2026
```

Примеры синтетические: `payment:12345` и `report:1` должны реально существовать
и иметь соответствующие суммы. Будущие даты денежных операций не принимаются.
Последний пример станет допустим после фактического платежа в 2027 году.

| kind | Назначение |
|---|---|
| income | Собственный доход; внешний доход допускается без source_key |
| transit | Деньги/возврат денег стороннего репетитора, налоговый доход 0 |
| agent_fee | Фактически полученная комиссия по report:ID, полностью по отчёту |
| refund | Возврат ранее учтённого дохода, нужен original_id |
| tax_payment | Погашенный УСН за tax_year, отдельно от пополнения ЕНС |
| reverse | Исправление полной исходной записи её датой, нужен original_id |
| exclude | Исключение источника из учёта: сумма 0, source_key и причина обязательны |

`operation_id` — ваш стабильный уникальный ID операции выписки/документа.
`source_key` — ключ из списка сверки, не используется дважды.
`original_id` — operation_id исправляемой записи/поступления.
`amount` всегда неотрицательная сумма в рублях; знак возврата/сторно вычисляется.
`tax_year` для доходов совпадает с годом даты; для уплаты УСН может быть 2026
при дате платежа в следующем году. Пустое поле означает год даты.

Импорт целиком выполняется в транзакции. Повтор тех же ID с теми же данными
ничего не добавляет, несовпадающие данные под прежним ID отклоняются.
Ошибочная строка отменяет весь пакет. После новых записей/исправлений сверку
нужно подтвердить повторно. Прямого удаления финансовых записей в интерфейсе нет.

`reverse` разрешён один раз на запись без связанных возвратов/исправлений.
Ошибочный возврат можно сторнировать отдельно. Исправленный доход при необходимости
вносится новым ID без повторного source_key со ссылкой на первичный документ.
Частичное удержание комиссии по отчёту не привязывается к целому report:ID:
используйте документированное исключение источника и отдельные подтверждённые
строки income по фактам удержания, проверяя отсутствие двойного дохода.

## Взносы и расчёт

Ввод: `год_взноса;fixed/extra;обязательство;использовано_вне_бота;часть_уменьшения;дата_доступности;документ`.

Каждая дата — отдельная часть уменьшения. Повтор на ту же дату заменяет эту
часть; остальные даты сохраняются. Сумма всех частей плюс использованная вне
бота сумма не может превышать обязательство. Обязательство и внешнее использование
общие для всех частей одного взноса; их изменения сохраняются в аудите.
Дата доступности относится к праву уменьшения, не обязательно к дате уплаты.

Полное годовое обязательство 2026: фиксированная часть 57 390 ₽,
дополнительная — 1% с дохода свыше 300 000 ₽, максимум 321 818 ₽.
**Полная фиксированная сумма не применяется автоматически:** для неполного года
и освобождений нужна фактическая сумма обязательства. Дата начала УСН сама по себе
не устанавливает дату регистрации ИП и периоды освобождения при других режимах.
Оценка 1% показывается отдельно и автоматически налог не уменьшает.
Допвзнос за 2025 допускается в уменьшение 2026 только в неиспользованной части.
Для ИП без указанных выплат ограничение уменьшения в 50% не применяется.

Расчёт ведётся в копейках/Decimal; налог после уменьшения округляется до полных
рублей. Пример: доход за 9 месяцев 100 000 ₽, доступное уменьшение 2 000 ₽ →
налог 4 000 ₽. Если к концу года доход остался тем же, а уменьшение увеличилось
до 7 000 ₽, налог 0 ₽, ранее начисленный аванс к уменьшению 4 000 ₽.

«Разница налога и платежей» — не сальдо ЕНС: пополнение единого счёта может
погашать иные обязательства. Платежи учитываются по состоянию на сегодня,
налог — за выбранный период. Неотработанные авансы за собственные услуги
уже являются доходом при поступлении; завершение урока не ждём.

## Границы реализации и запуск

- Проверены правила **2026 года**; 2027 как налоговый год требует обновления правил.
  Платежи в 2027 за обязательство 2026 поддерживаются.
- Не реализованы банковский API, НДС, зарплата/НДФЛ, торговый сбор, другие режимы,
  подача декларации/уведомлений, перечисление денег и запрос сальдо ЕНС.
  Достижение 20 млн ₽ по учтённым доходам вызывает напоминание отдельно проверить НДС;
  это не полная проверка освобождения (нужны также сведения прошлых периодов).
- PDF включает титульный лист и раздел I для указанного профиля; это не декларация.
  Разделы для УСН «доходы минус расходы» и торгового сбора не формируются.
- Записи до УСН не становятся доходом УСН автоматически; переходящие расчёты
  и возвраты доходов прошлых налоговых лет требуют отдельного разбора.
- Ввод и выгрузки доступны только ADMING_ID в Telegram. VK сохраняет прежнее ограничение админки.
- `tax_*` таблицы создаются лениво при первом открытии раздела. Существующие
  операционные таблицы не изменяются. Требуются зависимости requirements.txt
  и шрифт DejaVu Sans/Liberation Sans, как для агентских отчётов.
- Резервное копирование БД должно включать tax_entries, tax_audit, tax_exports,
  tax_sources, tax_profile, tax_contribution_allocations.
- Этот PR построен поверх #11. Старый п. 4.3 `legal/01_agent_agreement.md`
  пока описывает прежнюю месячную комиссию: текст договора нужно отдельно
  привести в соответствие с согласованным правилом двух выплат до его использования.

Проверки: `python -m unittest discover -s tests -v`. Транзакционные тесты
используют отдельную PostgreSQL БД из `TAX_TEST_DATABASE_URL` и временную схему,
которую удаляют после теста. Production DATABASE_URL для этого не используется.
GitHub Actions запускает PostgreSQL 16 service для этих тестов.
